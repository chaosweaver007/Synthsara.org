## Status update rule

A status may move forward only when the required evidence appears.

### Static prototype to functional proof

Requires working behavior, reproducible setup, tests, visible limitations, and no deceptive controls.

### Functional proof to pilot

Requires named participants or community scope, consent, risk review, metrics, support, correction mechanisms, and documented results.

### Pilot to production

Requires appropriate identity, security, privacy, accessibility, monitoring, incident response, data governance, legal review where applicable, sustainable operations, and accountable ownership.

### Specification to empirical evidence

Requires a defined method, observable results, reproducible artifacts, and claim limits. A narrative simulation or assistant evaluation does not satisfy this transition.

## Immediate red labels for the existing prototype

Until repaired, any page rendering the following must display a prominent demonstration label:

- global environmental, social, or economic metrics;
- proposal IDs, votes, deadlines, resonance scores, or participation controls;
- data-sharing toggles, recipients, transactions, or compensation;
- POWERcoin or WORTH wallet balances and transaction histories;
- buttons suggesting votes, earnings, proposals, marketplace actions, or external manifestation;
- Sarah AI functions not actually connected to the bounded Genesis route.

The preferred repair is not merely a footer disclaimer. The label belongs inside the component, immediately beside the simulated content.
