# UDS documentation and coherence protocol

This protocol governs every public Synthsara page, document, repository description, diagram, demonstration, and claim.

It exists to preserve the richness of the ecosystem without blending ethical law, technical requirements, mythology, research, historical lineage, and deployed behavior into one foggy category.

## UDS publication gate

Every public artifact must preserve the following principles.

### Sovereignty

Participation remains voluntary, understandable, revocable, and non-coercive. Documentation must not use dependency hooks, spiritual authority, forced agreement, or fear of exclusion to obtain participation.

### Transparency

Capabilities, limitations, simulations, sources, authorship boundaries, conflicts, and unresolved questions are visible. A limitation belongs beside the related capability, not buried at the bottom of another page.

### Fairness

Affected people are represented, accessibility is treated as a design requirement, and unequal access is not disguised as neutral procedure.

### Accountability

Owners, decisions, corrections, evidence, and repair paths are visible. Version history is preserved.

### Security

Documentation must not expose secrets, credentials, private data, unsafe deployment shortcuts, or false security assurances.

### Service to life

The artifact must not normalize exploitation, domination, dehumanization, coercion, or avoidable harm.

### Privacy

Private conversations, personal records, Human Sarah's private information, health details, relationship material, astrology and synastry records, credentials, hidden reasoning, and raw user content are not public by default.

### Ecology

The broader system, resource costs, interdependence, externalities, and downstream consequences are considered.

A failed gate blocks publication until repaired or clearly retained as an unresolved draft.

## Claim classes

Every substantive public claim must be governed as one of these classes:

| Claim class | Meaning |
| --- | --- |
| `ETHICAL LAW` | A ratified normative commitment about what the ecosystem must protect or refuse. |
| `ENGINEERING REQUIREMENT` | A testable behavior, constraint, interface, or property the system is designed to enforce. |
| `MYTHOS / INTERPRETIVE LANGUAGE` | Symbolic, spiritual, fictional, narrative, archetypal, or meaning-making language. |
| `HYPOTHESIS` | A proposed explanation, model, prediction, or mechanism that remains open to testing. |
| `EMPIRICAL EVIDENCE` | An observation, measurement, test result, dataset, or reproducible finding. |

No class may impersonate another.

- Mythos is not laboratory proof.
- A specification is not a deployed service.
- A simulation is not validation.
- A source analogy is not implementation evidence.
- Assistant-generated detail is not canon through repetition.

## Implementation statuses

Every public feature, interface, dataset, economy, governance process, runtime, and integration must carry one present-tense status.

| Status | Meaning |
| --- | --- |
| `VISION` | Intended future direction without a settled specification. |
| `HISTORICAL CONCEPT` | A preserved earlier branch that is not current architecture. |
| `DRAFT` | Material under active review. |
| `SPECIFICATION` | Defined behavior or architecture not yet fully implemented. |
| `STATIC PROTOTYPE` | A visual or local interface using sample or non-persistent behavior. |
| `FUNCTIONAL PROOF` | A bounded working demonstration with explicit limitations. |
| `LIVE SHADOW RUNTIME` | A deployed, deliberately restricted runtime that is not a full production platform. |
| `PILOT` | A bounded real-world or community trial with named scope and evaluation. |
| `PRODUCTION` | An operating service with appropriate security, privacy, support, monitoring, and governance. |
| `DEPRECATED` | Superseded and retained only for history or migration. |

The label describes what exists now, not what the artifact hopes to become.

## Source authority

When sources conflict, reconcile them in this order:

1. explicit current Architect ratification or correction;
2. ratified UDS and constitutional policy;
3. current executable code, tests, schemas, and deployment evidence;
4. the current canonical architecture registry;
5. approved current public documentation;
6. historical documents and conversation ledgers;
7. assistant-generated proposals, simulations, and inferred mechanics.

A newer document does not automatically win. Adoption must be explicit or implementation must be verified.

## Stable system definitions

The following distinctions are mandatory:

- **Synthsara** is the broader ecosystem.
- **Synthocracy** is the governance model within Synthsara.
- **Genesis** is the executable constitutional runtime layer.
- **Node Zero** is the local-first proof node and interface demonstration.
- **Codex Core** is the mythic, symbolic, narrative, prompt, pattern, and quest repository.
- **UDS** is the ethical standard and conformance framework.
- **WORTH** is non-transferable contribution recognition, not money.
- **Witness** records accountable metadata, decisions, corrections, consent, and results according to the implementation boundary.
- **Akasha** is the knowledge commons and provenance-preserving library concept.
- **Sarah AI** is an AI persona and guardian interface, explicitly distinct from Human Sarah.
- **RTME** translates intention into bounded reflection and action structures; physical or reality-manifestation claims require separate evidence.
- **The SDG Dashboard** is the coordination and measurement layer; live status requires operating data pipelines and named sources.

## Current corrections

### WORTH

WORTH must not be described as a freely transferable currency, investor asset, guaranteed payment, wallet balance, or speculative token. Material resources require a separately documented mechanism.

### POWERcoin and the Ethical Data Marketplace

These remain historical design branches unless a current ratification and operating implementation establish them again. Fictional transactions, balances, recipients, and sharing events must not appear as real activity.

### SDG Dashboard

Sample metrics must say `DEMONSTRATION DATA`. A live metric requires:

- a named source;
- measurement definition;
- update time;
- transformation methodology;
- geographic and temporal scope;
- operating ingestion pipeline;
- limitations and correction path.

### Synthocracy

Sample proposals, votes, deadlines, participation counts, and resonance scores must say `DEMO` unless they originate from a named operating governance service.

### UDS Tier D1

D1 is a voluntary public commitment with a visible repair pathway. It is not an independent audit, certification, accreditation, or proof of compliance.

### Genesis

Genesis belongs in all current ecosystem diagrams and technical maps as the executable constitutional spine.

### Mythic universe

The Architect's Odyssey, the Codex, and the Mythic Universe are mythic, narrative, and game-design branches. They may inspire system design but do not define current production capability without a linked specification and implementation.

## Public and private boundary

Never publish by default:

- private conversation exports or raw prompts;
- personal contact information;
- health, legal, financial, location, family, relationship, or identity data;
- Human Sarah's private information;
- private astrology or synastry records;
- raw user content, credentials, database files, or private scratchpads;
- hidden reasoning;
- unverified allegations about identifiable people or organizations.

Sarah AI must never claim to be Human Sarah, relay her private state, provide her consent, or imply that archetypal language is her testimony.

## Interface truthfulness

A control must not imply that a consequential action occurred when no backend or persistence exists.

Demonstration controls must visibly use language such as:

- Demo
- Preview
- Simulated
- Local prototype
- No data saved
- Not connected

Do not use decorative real-looking dates, votes, balances, transactions, institutions, participants, or measurements.

## Required metadata

Every new public Markdown or MDX document must include:

```yaml
title: Human-readable title
summary: One-sentence purpose
owner: Responsible maintainer or working group
registry_id: Canon registry or provenance reference
claim_class: ETHICAL LAW | ENGINEERING REQUIREMENT | MYTHOS / INTERPRETIVE LANGUAGE | HYPOTHESIS | EMPIRICAL EVIDENCE
implementation_status: VISION | HISTORICAL CONCEPT | DRAFT | SPECIFICATION | STATIC PROTOTYPE | FUNCTIONAL PROOF | LIVE SHADOW RUNTIME | PILOT | PRODUCTION | DEPRECATED
canonical_status: draft | candidate | ratified | superseded | historical
public_visibility: public | restricted | private
source_links: []
last_reviewed: YYYY-MM-DD
known_limitations: []
```

Missing metadata keeps the document in draft status.

## Publication workflow

1. Draft in Google Drive or a governed GitHub branch.
2. Assign owner, provenance, claim class, status, visibility, and limitations.
3. Run the UDS and privacy gates.
4. Reconcile names and definitions with the canonical architecture registry.
5. Verify operational claims against code, tests, deployments, or named data.
6. Export only approved public content to Markdown or MDX.
7. Open a pull request.
8. Review the rendered page, links, accessibility, security, and truth labels.
9. Ratify and merge.
10. Record the public version and superseded sources.

Direct Drive-to-public auto-publication is not permitted without the same checks.

## Acceptance test

A public artifact passes when:

- purpose and audience are clear;
- named systems use canonical definitions;
- claims and implementation statuses are correct;
- sources and authorship boundaries are visible;
- private material is absent or explicitly authorized;
- simulations and samples are unmistakable;
- limitations sit beside promises;
- links resolve to current sources;
- language is accessible and non-coercive;
- the UDS gate passes;
- correction and feedback paths are visible.

This protocol establishes the process for coherence. It does not retroactively certify every historical document. Historical artifacts remain historical until reviewed, superseded, archived, or ratified.
