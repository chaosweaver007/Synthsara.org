# Synthsara public source reconciliation ledger

This ledger prevents source documents from silently borrowing authority from one another. It records what each source family may support, what it cannot establish, and what correction is required before it governs the public site.

A historical ledger remains historical evidence. A mythic bible remains mythic or game-design canon. A source architecture remains a specification until implementation evidence exists. A repository establishes only what its current code, tests, and deployment evidence support.

## Authority spine

| Surface | Current authority |
| --- | --- |
| Synthsara.org | Public portal and approved public documentation |
| Genesis | Executable constitutional spine and bounded Gate Zero runtime |
| Node Zero | Local-first functional proof node |
| Codex Core | Mythic, narrative, symbolic, prompt, pattern, and quest canon |
| Google Drive | Working archive and editorial workshop with mixed authority levels |
| GitHub | Public code, tests, policies, schemas, version history, and approved documentation |

## Current executable sources

### Genesis

**Role:** current executable constitutional runtime evidence.  
**Claim class:** `ENGINEERING REQUIREMENT` and `EMPIRICAL EVIDENCE`.

Supported claims include bounded public routes, strict ingress validation, monotonic Gate Zero restrictions, constitutional context, bounded persona adaptation, UDS reflection, and metadata-only receipt behavior.

## Cross-source corrections

- **WORTH:** non-transferable recognition, not money.
- **POWERcoin and Ethical Data Marketplace:** historical unless explicitly re-ratified and implemented.
- **Genesis:** mandatory in current technical architecture maps.
- **Sarah AI:** distinct from Human Sarah and unable to supply her consent, private knowledge, or testimony.
- **Synthocracy:** governance model within Synthsara, not proof of an operating world government.
- **SDG Dashboard:** specification/static prototype until live pipelines and methodology exist.
- **Witness:** describe the actual implementation boundary rather than claiming one universal immutable ledger.
- **RTME:** bounded intention structuring; external physical claims require separate evidence.
- **D1:** public promise and repair path, not an audit or certification.
- **Mythic Universe and Architect’s Odyssey:** mythic/game branches, not production evidence.
- **Simulations:** discovery and stress-test tools, not empirical validation.

## Reconciliation workflow

For each remaining document family:

1. identify the canonical candidate and duplicate family;
2. classify public, restricted, private, or sensitive visibility;
3. assign claim class and implementation status;
4. identify user-authored, ratified, mixed-author, external, and assistant-generated portions;
5. apply current corrections;
6. separate mythic, scientific, legal, medical, economic, and engineering layers;
7. verify operational claims against code, tests, deployments, or named data;
8. record unresolved claims and privacy concerns;
9. export only the approved public derivative to GitHub;
10. preserve source revision, lineage, correction, and supersession history.

## Known limitations and completion boundary

This ledger establishes a coherent authority map for the supplied source set. It does not claim that every conversation, duplicate, PDF, spreadsheet row, private Drive file, or historical branch has already been rewritten. Those sources remain governed by this ledger and the UDS protocol until reviewed in controlled batches.
