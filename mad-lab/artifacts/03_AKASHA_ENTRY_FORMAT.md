# AKASHA ENTRY FORMAT
## Synthsara Mad Lab — Artifact 03

---

### What Is the Akasha?

The **Akasha** is a knowledge commons — a shared repository of information with clear provenance. It's designed to:

- Preserve what matters
- Credit contributions properly
- Enable verification
- Prevent extraction and theft
- Remember without surveilling

> "If it matters, we record it." — The Archivist

---

## THE ENTRY FORMAT

Every Akasha entry follows this structure:

```
┌─────────────────────────────────────────────────────────┐
│ AKASHA ENTRY                                            │
├─────────────────────────────────────────────────────────┤
│ WHAT:    [Title/Name of the thing]                      │
│ WHY:     [Purpose/Context/Significance]                 │
│ SOURCE:  [Where this came from]                         │
│ DATE:    [When this was created/recorded]               │
│ OWNER:   [Who is responsible/credited]                  │
│ STATUS:  [Current state]                                │
│ LINKS:   [Related entries]                              │
└─────────────────────────────────────────────────────────┘
```

---

## FIELD DEFINITIONS

### WHAT
**The title or name of what you're documenting.**

- Be specific and searchable
- Use consistent naming conventions
- Include version numbers if applicable

**Examples:**
- "Signal Checklist v1.0"
- "EP01 Script Draft 3"
- "Governance Charter — Community Vote Results"

---

### WHY
**The purpose, context, or significance of this entry.**

Answer:
- Why does this exist?
- Why does it matter?
- What problem does it solve?

**Keep it brief** — 1-3 sentences. If you need more, link to a longer document.

**Example:**
> "This checklist helps viewers distinguish signal from noise before engaging online. It's the primary artifact from Episode 1 and the foundation for attention discipline."

---

### SOURCE
**Where this came from — the provenance chain.**

Include:
- Original creator (if not you)
- Inspiration sources
- Data sources
- Previous versions this builds on

**Be honest about origins.** If you built on someone else's work, say so.

**Examples:**
- "Original creation by Steven, refined with Sarah"
- "Adapted from [Author]'s framework, with modifications"
- "Synthesized from community discussion on [date]"
- "Data from [source], accessed [date]"

---

### DATE
**When this was created or last updated.**

Format: `YYYY-MM-DD`

If tracking versions, include:
- Created: [date]
- Last Updated: [date]
- Version: [number]

**Example:**
```
Created: 2025-01-15
Last Updated: 2025-01-26
Version: 1.2
```

---

### OWNER
**Who is responsible for this entry.**

This is about **accountability**, not control.

The owner:
- Can update the entry
- Is the point of contact for questions
- Is credited for the contribution

**For collaborative work**, list all contributors:
```
Owner: Steven (lead)
Contributors: Sarah, Wes, Community Review
```

---

### STATUS
**The current state of this entry.**

Standard statuses:

| Status | Meaning |
|--------|---------|
| `DRAFT` | Work in progress, not ready for use |
| `REVIEW` | Ready for feedback, not finalized |
| `ACTIVE` | Current, approved, in use |
| `ARCHIVED` | No longer current, kept for reference |
| `DEPRECATED` | Replaced by newer version |
| `DISPUTED` | Accuracy or ownership contested |

---

### LINKS
**Related entries in the Akasha.**

Connect this entry to:
- Prerequisites (what you need to understand first)
- Related concepts (adjacent ideas)
- Builds on (what this extends)
- Extended by (what builds on this)

**Example:**
```
Links:
- Prerequisites: None (entry point)
- Related: Consent Boundary Template, Attention Discipline
- Builds on: N/A
- Extended by: EP02 Script, Advanced Signal Analysis
```

## PRINCIPLES

### 1. Receipts Without Paranoia

Documentation should enable:
- Verification (can we check this?)
- Attribution (who contributed?)
- Learning (what can we learn from history?)

Documentation should NOT enable:
- Surveillance (tracking people's behavior)
- Punishment (using records as weapons)
- Control (gatekeeping access to knowledge)

### 2. Ledger Over Pattern

> "Pattern must never overwrite record."

The Akasha preserves **what actually happened**, not just the meaning we make of it.

- Record the facts first
- Interpretation comes second
- Both are valuable; neither erases the other

### 3. Non-Extractive Crediting

When you use someone's work:
- Credit them clearly
- Link to the original
- Don't claim it as your own
- Ask permission for derivative works

When someone uses your work:
- Expect credit
- Don't expect control
- Contribute to the commons

## QUICK REFERENCE

### Minimum Viable Entry

If you're in a hurry, capture at least:

```
WHAT: [Title]
WHY: [One sentence]
SOURCE: [Origin]
DATE: [Today]
OWNER: [You]
```

You can expand later.

### When to Create an Entry

Create an Akasha entry when:
- You make a decision that affects others
- You create something others might use
- You learn something worth preserving
- You want to credit someone's contribution
- You need to track versions or changes

### When NOT to Create an Entry

Don't create entries for:
- Private thoughts or drafts (until ready)
- Sensitive personal information
- Information that could harm someone
- Things that don't need to persist
